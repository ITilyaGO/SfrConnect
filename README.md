# SfrConnect — чтение и запись номера чипа

Библиотека C# / .NET 8 для Windows и отдельная консольная диагностика.
Реализованы обнаружение SFR USB HID, открытие/закрытие соединения и один
звуковой/световой сигнал, обнаружение доступного чипа, чтение и запись его номера.
Без флага очистки запись меняет только ячейку 03 с номером. Доступны отдельная
очистка отметок и присвоение номера с очисткой. Служебные чипы автоматически переводятся
в обычные при изменении, неизвестные форматы не изменяются.
Интеграции с базой данных и интерфейсом OrientCalculator пока нет.

## Тестовое окно

Проект `SfrConnect.TestApp` — отдельное приложение WPF для Windows / .NET 8.
В Visual Studio назначьте его запускаемым проектом и нажмите Ctrl+F5.
Либо запустите `SfrConnect.TestApp/bin/Release/net8.0-windows/SfrConnect.TestApp.exe`
после сборки Release. Рядом с EXE должны оставаться все файлы из каталога сборки.

1. Закройте другие программы, работающие со станцией. Нажмите «Обновить».
2. Выберите станцию и нажмите «Подключить». Начнётся фоновое чтение каждые 0,5 с.
3. Введите новый номер 0–39999 и нажмите «Записать» — чип ещё не нужен.
   Галочка «Очистить отметки при записи» включает очистку перед присвоением.
   Кнопка «Очистить отметки, сохранив номер» выполняет только очистку.
   Для служебного чипа очистка обязательна независимо от галочки: служебный режим
   снимается и чип переводится в обычный. Одно прикладывание без команды ничего не меняет.
4. Приложите один чип и дождитесь подтверждения повторным чтением и сигнала.
5. Уберите чип примерно на секунду. Можно заранее задать следующую команду:
   окно дождётся снятия предыдущего чипа, затем появления следующего.
6. «Отменить ожидание» прекращает поиск. После начала записи проверка завершается
   даже при отмене: окно сообщает фактический результат.

Без команды «Записать» прикладывание чипа ничего не записывает. После попытки записи
следующая команда сначала ждёт два последовательных ответа о недоступности чипа;
изменение номера, остановка чтения и переподключение это требование не снимают.
Это защита в рамках одного запуска окна, а не доказательство уникальности чипа.
Во время команды номер фиксируется, другие операции со станцией недоступны.

«Остановить чтение» приостанавливает опрос, «Отключить» освобождает USB.
При ошибке обмена соединение закрывается: проверьте подключение и нажмите «Подключить»
снова (если путь устройства изменился, сначала «Обновить»).
Снятие или перемещение чипа до отправки записи не закрывает соединение:
окно продолжает ждать устойчивого чтения. Если запись уже отправлена, но чип убран
до проверки, результат остаётся неподтверждённым и запись не повторяется.
Неподтверждённая запись не повторяется автоматически; сначала прочитайте чип заново.
Закрытие окна дожидается текущего обмена, чтобы не прервать проверку записи.
В журнале хранятся последние 500 сообщений; их можно сохранить в текстовый файл.

USB-операции выполняются в фоновой задаче и не перекрываются. Тесты состояния окна
проверяют блокировку повторной записи, снятие чипа и сброс устаревшего номера.

На проверенной станции номера 18000, 20000 и 39999 прочитаны успешно. После записи
40000 внешним приложением станция отвечала `2A 06`; возврат к 39999 восстановил чтение.
Это наблюдение не определяет причину: формат записи приложения или ограничение станции.

## Проверка на станции

1. Подключите USB-станцию сопряжения SFR. Чип не нужен.
2. Закройте другие программы, использующие станцию.
3. Откройте `SfrConnect.sln` в Visual Studio. Назначьте
   `SfrConnect.Diagnostics` запускаемым проектом и нажмите Ctrl+F5.
4. Введите `list`. Для известного варианта ожидаются VID `2047`, PID `0301`.
5. Введите `open`. Должны появиться сообщения об открытии и закрытии соединения.
6. Введите `beep`. Проверьте сигнал/индикатор станции.
7. Приложите один чип, держите его неподвижно и введите `read`.
   Программа покажет номер и исходные пакеты TX/RX.
8. Уберите чип и повторите `read`. Ответ `2A 06` выводится как
   «чип не обнаружен или недоступен для чтения», а отсутствие ответа — как тайм-аут.
9. Для изменения номера приложите чип и введите, например, `write 123`.
   Текущий номер знать не требуется; библиотека сама прочитает ячейку перед записью.
   Короткая форма работает при одном подключённом интерфейсе SFR.
   Для проверки ожидаемого старого номера остаётся форма `write 2 3`:
   первый аргумент — ожидаемый текущий номер, второй — новый.
   Если текущий номер отличается, команда записи не отправляется.
   Держите чип на станции до сообщения о подтверждении повторным чтением.

При нескольких интерфейсах укажите номер из текущего списка SFR:
`open 1`, `beep 1`, `read 1`, `write 2 3 1`.
В последнем примере 1 — номер устройства. Нумерация может измениться после переподключения.
Каждая команда заново перечисляет устройства и выводит выбранный путь.
Если SFR не найдена, используйте `list --all`: она показывает все HID-устройства
и ничего им не отправляет. Номера из этого общего списка не используются для
`open`, `beep`, `read` и `write`.

Из PowerShell в каталоге решения:

```powershell
dotnet run --project .\SfrConnect.Diagnostics -- list
dotnet run --project .\SfrConnect.Diagnostics -- open
dotnet run --project .\SfrConnect.Diagnostics -- beep
dotnet run --project .\SfrConnect.Diagnostics -- read
dotnet run --project .\SfrConnect.Diagnostics -- list --all
dotnet test .\SfrConnect.sln
dotnet build .\SfrConnect.sln -c Release
```

Без аргументов программа запускается в интерактивном режиме. В режиме командной
строки код завершения 1 означает ошибку; пустой список или ответ «чип недоступен»
сами по себе не являются ошибкой соединения (код 0).
Журнал выводится в консоль и автоматически на диск не записывается.
Для сохранения используйте, например:

```powershell
dotnet run --project .\SfrConnect.Diagnostics -- beep 2>&1 | Tee-Object -FilePath .\sfr-diagnostic.txt
```

## Что означает результат

- Найден интерфейс: Windows видит устройство с ожидаемыми VID/PID.
- Соединение открыто: дескриптор соответствует известному формату и HID-поток открыт.
- TX завершён: операция записи прошла без ошибки. Это **не подтверждение**
  выполнения команды станцией. Подтвердите звук или индикацию непосредственно.
- Тайм-аут/ошибка записи: сохраните полный вывод, включая тип ошибки и TX.
- Неподдерживаемый дескриптор: команда не отправляется; нужен разбор этой модели.

Команда `read` проверяет длину HID-отчёта, Report ID, границы пакета, код команды,
адрес ячейки и допустимость цифр номера. При тайм-ауте, повреждённом ответе или
исчезновении чипа в середине чтения частичный результат не возвращается.
Для сигнала ответ по-прежнему не ожидается.
Автоматические тесты используют имитацию потока и сохранённые примеры реальных
ответов, но не обращаются к USB.

## Использование DLL

```csharp
using SfrConnect;

var devices = SfrStation.FindDevices();
// Select the desired DevicePath explicitly if there is more than one interface.
if (devices.Count == 1)
{
    using var station = SfrStation.Open(devices[0].DevicePath, Console.WriteLine);
    station.Beep();
    var card = station.ReadCardNumber();
    Console.WriteLine(card is null ? "Чип недоступен" : $"Номер: {card.Number}");
}
```

Базовые методы SfrStation синхронные: для WPF вызывайте их из фоновой задачи. Команда SfrNumberWriter.AssignAsync уже выполняет USB-обмен в фоне.
Передача команды ограничена тайм-аутом 2 секунды; ожидание её ответа — 1 секунда.
После сигнала DLL выдерживает паузу 300 мс под блокировкой обмена, как в SportOrg:
чтение и другие команды не отправляются сразу вслед за сигналом.
Открытие само по себе сигнала не отправляет.
Для подключения к OrientCalculator предпочтителен ProjectReference.
При ручном копировании нужны `SfrConnect.dll` и зависимость `HidSharp.dll`
из каталога сборки диагностической программы.

После ошибки обмена `ReadCardNumber()` или `WriteCardNumber()` закройте и заново откройте соединение.
Исключение — `SfrCardNotReadyException`: станция ответила корректно, но чип исчез или
изменился до записи. Частичные данные не возвращаются, повторное чтение разрешено.
В протоколе нет номера транзакции: запоздалый ответ нельзя безопасно использовать
при повторной попытке. После ответа `2A 06` на начальный запрос повтор разрешён.
Консольные команды `read` и `write` всегда сами открывают и закрывают соединение.

### Запись из DLL

Для сценария «запиши N, когда появится чип» используйте одну команду:

```csharp
using var station = SfrStation.Open(selectedDevicePath);
var writer = new SfrNumberWriter(station);
using var cancel = new CancellationTokenSource();
// A UI cancel button can call cancel.Cancel().
try
{
    var result = await writer.AssignAsync(123, cancel.Token);
    if (result.Success)
    {
        Console.WriteLine($"Проверенный номер: {result.Card.Number}");
        if (!result.SignalSent)
            Console.WriteLine($"Номер записан, но сигнал не отправлен: {result.SignalError}");
    }
    else
    {
        Console.WriteLine($"Результат не подтверждён: {result.Error}");
        // Card is null; the requested number may already have been written.
        // Reopen only if RequiresReconnect is true, then read the card.
    }
}
catch (OperationCanceledException)
{
    Console.WriteLine("Ожидание отменено; запись не выполнялась.");
}
```

`AssignAsync` ждёт чип без ограничения времени, читая его каждые 250 мс после
завершения предыдущего запроса. Для ограничения времени можно использовать
`CancellationTokenSource(TimeSpan.FromSeconds(30))`. Отмена проверяется и после
предварительного чтения, непосредственно перед попыткой записи. После этой границы
DLL обязательно проверяет запись; отмена не скрывает успех или неподтверждённую запись.
Ошибки USB завершают команду, автоматического повтора отправленной записи нет.
Если чип исчез или изменился во время поиска либо предварительного чтения, команда
продолжает ожидание. После подтверждения записи номера ответ `2A 06` при проверке
запускает ожидание возврата чипа до 5000 мс с повтором контрольного чтения через
200 мс. Срок отсчитывается от первого ответа о недоступности и не перезапускается
при частичном чтении. При успехе ожидание заканчивается сразу. Команда записи не повторяется. Номер, тип и маркер должны совпасть;
несовпадение останавливает проверку сразу. Маркер не является UID: во время команды
нельзя подменять чип другим. Тайм-ауты и повреждённые ответы не повторяются.

На реальной станции также наблюдался ответ записи `2A 08` вместо `2A 55`.
Его точная расшифровка пока не подтверждена. При записи только номера этот ответ
запускает контрольное чтение с тем же ожиданием возврата чипа: успех разрешён лишь
после совпадения номера, типа и маркера. Сам по себе `2A 08` не подтверждает запись,
не вызывает повторной записи и не требует переподключения. Ошибка последующего
USB-обмена по-прежнему требует переподключения. При очистке и преобразовании
служебного чипа после `2A 08` проверяются текущая записанная ячейка, ожидаемый
заголовок и маркер. Если чип недоступен, применяется тот же срок ожидания возврата.
Следующая запись разрешается только после совпадения данных; повторной отправки
уже выполненной записи нет. Неподтверждённая ячейка останавливает очистку обычным
результатом `Success = false`, `Failure = ClearUnverified`, без переподключения.
Заголовок ячейки 04 при временной потере чипа проверяется с ожиданием и после `2A 55`.
Итоговый полный проход памяти остаётся обязательным перед сигналом успеха.
При `2A 06` в итоговом проходе очистки или завершающей проверке номера DLL ждёт
возврата чипа в пределах `VerificationReturnTimeoutMs`. После возврата весь проход
02–7F и проверка номера/заголовка/маркера выполняются заново, без записей.
Повторное исчезновение не продлевает срок. Истечение ожидания или несовпадение
прочитанных данных возвращает `Success = false`, `Failure = ClearUnverified`,
`RequiresReconnect = false`: соединение остаётся доступным для чтения.
Настоящий тайм-аут или повреждённый USB-ответ по-прежнему требует переподключения.

`AssignAsync` и `ClearAsync` возвращают неподтверждённое изменение обычным результатом:
`Success = false`, `Card = null`, `SignalSent = false`, `CardMayHaveChanged = true`.
`Failure` различает `WriteUnverified` и `ClearUnverified`, `Error` содержит причину,
`RequestedNumber` — запрошенный номер, `LastAttemptedCell` — последнюю изменяемую ячейку.
При исчезновении чипа во время проверки номера исключение не создаётся и соединение
остаётся доступным для чтения (`RequiresReconnect = false`). При нарушении USB-обмена
или других сбоях очистки `RequiresReconnect = true`: соединение нужно открыть заново.
Отмена ожидания, неверные аргументы и ошибки до попытки изменения сохраняют прежний контракт.

Если чип снят при подготовительном чтении памяти для очистки, DLL ждёт его возврата
в пределах `VerificationReturnTimeoutMs` и строит план очистки заново. Один ответ
`2A 06` не считается доказательством неподдерживаемого размера памяти. После возврата
проверяются исходные маркер и заголовок; другой чип не изменяется. Если подготовку
завершить не удалось, команда возвращает `Success = false`, `Failure = PreparationFailed`,
`CardMayHaveChanged = false`, `RequiresReconnect = false`, `LastAttemptedCell = null`.
Записей и сигнала не было. Тестовое окно сообщает «Чип не изменён» и не требует снятия
чипа как после выполненной записи; команду можно запустить повторно без переподключения.
Отмена работает и во время этого ожидания. Синхронный `ClearCard` сохраняет исключение
`SfrCardNotReadyException` для незавершённой подготовки, но не блокирует соединение.

Настройки задаются при открытии соединения и действуют для всех команд записи номера:

```csharp
using var station = SfrStation.Open(selectedDevicePath, options: new SfrStationOptions
{
    VerificationReturnTimeoutMs = 5000,
    VerificationRetryIntervalMs = 200
});
var writer = new SfrNumberWriter(station);
```

Без настроек используются те же значения. `VerificationReturnTimeoutMs = 0`
отключает повторы; отрицательное время и неположительный интервал запрещены.
Это время ожидания возврата при подготовительном чтении очистки, проверке записи номера или отдельной ячейки после
`2A 08` при очистке (а также заголовка после `2A 55`) и при итоговой проверке очистки,
а не ограничение первоначального поиска чипа и не повтор всей очистки.
Начатая после возврата полная проверка может закончиться позже срока ожидания;
каждое USB-чтение ограничено собственным тайм-аутом транспорта.

При `Success = true` свойство `result.Card` содержит проверенный номер и служебное поле. `SignalSent` означает,
что USB-команда сигнала отправлена без ошибки; фактический звук протоколом не подтверждается.
Сбой сигнала не отменяет подтверждённую запись. Сигнал отправляется и когда нужный номер
уже был записан и DLL проверила совпадение всех четырёх байтов.
`CardCleared` равен `true`, если очистка проверена: она была запрошена флагом,
отдельной командой или выполнена автоматически для служебного чипа.

Не запускайте фоновое чтение и другие операции `SfrStation` одновременно с этой командой.
Используйте один `SfrNumberWriter` на соединение: повторный одновременный вызов отклоняется.
Перед закрытием соединения отмените ожидание и дождитесь завершения задачи.

Необязательный `IProgress<SfrAssignmentStage>` сообщает стадии `WaitingForRemoval`,
`WaitingForCard`, `Writing`, `Clearing`. Для серии чипов передайте `waitForRemoval: true`, если
после предыдущей записи снятие чипа ещё не было подтверждено. Команда дождётся двух
ответов об отсутствии чипа, затем появления чипа. Если `false`, уже лежащий чип
тоже подходит для выполнения команды.

Для немедленной записи без ожидания остаются базовые методы:

```csharp
using var station = SfrStation.Open(selectedDevicePath, Console.WriteLine);
var card = station.WriteCardNumber(newNumber: 123);
Console.WriteLine($"Проверенный номер: {card.Number}");
```

Допустимый новый номер: **0–39999**, согласно формату записи SFR basic.
Перегрузка `WriteCardNumber(expectedCurrentNumber: 2, newNumber: 3)`
дополнительно проверяет старый номер. Обе перегрузки предварительно читают чип
для проверки доступности и данных, затем проверяют записанное повторным чтением.
Чтение по-прежнему поддерживает три цифры с основанием 200, как в SportOrg.
При записи третий и четвёртый байты устанавливаются в 0, как в SFR basic и SFR phone.
Если все четыре байта ячейки уже равны ожидаемым, библиотека возвращает прочитанный
результат без повторной записи в память. При совпадающем номере и ненулевом четвёртом
байте запись всё равно выполняется, чтобы привести ячейку к этому формату.

После отправки записи проверяются номер, все четыре байта ячейки 03 и
неизменность служебного поля ячейки 01. Только после этого операция возвращает успех.
Совпадение текущего номера и служебного поля не гарантирует уникальность чипа:
на станции должен оставаться один и тот же чип.

`SfrWriteUnverifiedException` означает, что команда записи уже была попытана,
но результат не удалось подтвердить. Номер мог измениться даже при тайм-ауте
или ошибке USB. Автоматического повтора и отката нет.
Откройте соединение заново и выполните `read`, прежде чем решать, нужна ли новая запись.
Свойство `RequestedNumber` содержит запрошенный номер, `InnerException` — причину сбоя.

## Основание протокола и границы поддержки

Параметры взяты из существующего драйвера
`pysport/sportorg/libs/sfr/sfrreader.py`: VID=0x2047, PID=0x0301,
команда сигнала `3F 05 FD 03 01 04 FE`, буфер 64 байта с нулевым дополнением.
Это реализация обмена, а не полная спецификация всех моделей SFR.

В HidSharp первый байт буфера — Report ID, поэтому перед `3F` не добавляется
нулевой байт. Перед открытием проверяется наличие выходного отчёта ID=0x3F
длиной 64 байта в дескрипторе устройства. Иные варианты не угадываются.
HidSharp 2.6.4 используется как NuGet-зависимость.

- [Производитель: станция сопряжения использует USB HID](https://sfr-system.com/about_russian.html)
- [HidSharp: запись отчёта и Report ID](https://docs.zer7.com/hidsharp/html/3979308a-a35c-5e98-3525-e507d09a580d.htm)

### Чтение

Формат запросов дополнительно проверен по опубликованным производителем
[исходникам SFR basic](https://sfr-system.ru/software/SFRbasic_source.exe)
(`STFform.cpp`, `STFform.h`). Архив изучен без запуска исполняемого файла.

- Чтение ячейки 01: `3F 05 FD 01 01 02 FE`, дополнение нулями до 64 байт.
- Чтение ячейки 03: `3F 05 FD 01 03 04 FE`, дополнение нулями до 64 байт.
- Полезный ответ чтения: `3F 09 FD 01 <ячейка> <4 байта данных> <CS> FE`.
- Номер из ячейки 03: `b0 + b1 * 200 + b2 * 40000`, как в SportOrg.
  Нулевой номер допустим и отличается от отсутствия чипа.
- За объявленной длиной кадра станция возвращает произвольные байты.
  Они выводятся в журнал, но не используются при разборе.
- В проверенных ответах поле CS равно нулю и не совпадает с контрольной суммой
  полезных данных. Проверка CS ответов не применяется; целостность проверяется
  структурно. Это ограничение подтверждённого формата, не универсальная спецификация SFR.
- Ответ `3F 05 FD 2A 06 00 FE` означает, что чип недоступен для чтения.
  Другие коды не трактуются автоматически как отсутствие чипа.

Ячейка 01 повторно читается после номера. Её изменение или исчезновение чипа
прерывает операцию. Это **не уникальный идентификатор**: SFR basic при форматировании
пишет туда время. Чипы с одинаковыми данными ячейки 01 этим способом не различаются.
Поэтому на протяжении чтения держите один и тот же чип на станции.

### Запись

Запись ячейки 03: `3F 09 FD 02 03 b0 b1 b2 b3 CS FE`, дополнение нулями
до 64 байт. CS вычисляется по шести байтам от `02` до `b3` суммированием
с переносом старшего байта в младший.

При проверке на подключённой станции запись `2 → 3` дала ответ
`3F 05 FD 2A 55 00 FE`. Этот ответ допускает переход к проверочному чтению,
но сам по себе не считается доказательством успешной записи.
Другие ответы завершают операцию как неподтверждённую.

При записи обычного чипа без очистки ячейки 01 и 04 и отметки не меняются.
Для служебного чипа любая перегрузка записи выполняет перевод в обычный с очисткой.

### Служебные чипы и очистка

```csharp
var info = station.ReadCardInfo();
// Kind: Participant, Service or Unknown. Number is null for non-participant cards.

var assigned = await writer.AssignAsync(123, cancellationToken, clearCard: true);
var cleared = await writer.ClearAsync(cancellationToken);
if (cleared.Success)
    Console.WriteLine(cleared.Card.Number); // Original number, preserved during clearing.
```

Для немедленных синхронных операций доступны `station.ClearCard()` и
`station.WriteCardNumber(123, clearCard: true)`.

Проверка ячейки 04 выполняется в DLL до любой записи, в том числе в старых
перегрузках `WriteCardNumber`. Формат участника: первый байт счётчика не меньше 5,
остальные три байта нулевые. Известные служебные значения из SFR basic / SFR phone:
`00010000`, `01020000`, `02020000`, `03020000`, `05020000`, `09020000`,
`03030303`, `05050505`, а также префиксы `0109` и `0209`.
Другие форматы относятся к `Unknown` и тоже не изменяются.
Служебные чипы автоматически преобразуются в обычные при `AssignAsync`, `ClearAsync`,
`ClearCard` и во всех перегрузках `WriteCardNumber`, даже если `clearCard: false`.
До стирания служебных команд в ячейку 04 записывается `05000000`, затем очищается
память и проверяется итоговый тип `Participant`. Успех и сигнал разрешены только
после полной проверки. При отдельной очистке служебного чипа сохраняется корректный
номер 0–39999; если его нет или он вне этого диапазона, устанавливается 0.
При присвоении всегда устанавливается запрошенный номер.
Для неизвестного формата `SfrProtectedCardException` сообщает тип и исходный
заголовок; команда завершается без записи и без сигнала успеха.

Очистка повторяет подготовку в `ServiseNfc.zapisNum` из изученного SFR phone:
сначала чтение поддерживаемой памяти, затем обнуление непустых ячеек отметок, сброс ячейки 02,
установка `05000000` в ячейку 04 и текущего времени `00HHmmss` в ячейку 01.
При отдельной очистке обычного чипа все четыре байта номера сохраняются. При присвоении с очисткой
номер кодируется обычным способом. Ячейка 00 не меняется; стартовая отметка не создаётся.

**Граница поддержки:** очистка рассчитана на 128 ячеек (00–7F), как в SFR basic.
В отличие от телефона, размер памяти через NFC System Info по USB пока не определяется.
Перед изменениями читается весь поддерживаемый диапазон: это также находит старые
отметки за текущим счётчиком. Недоступные ячейки или счётчик за пределами диапазона
приводят к отказу до записи. Более ёмкие форматы требуют отдельного профиля;
не следует считать эту операцию гарантированной очисткой памяти за пределами 7F.

Уже пустые ячейки не перезаписываются. Перед каждой записью проверяются маркер и
заголовок чипа, после неё требуется подтверждение станции. Изменение заголовка
дополнительно сразу проверяется чтением, чтобы подтвердить отключение служебного режима.
Затем один проход чтения проверяет все ячейки 02–7F, включая пустой хвост, номер и
служебные поля; маркер проверяется по границам прохода, номер повторно проверяется
в конце. Только после этого подаётся сигнал и возвращается успех.
Для тестовых данных расчётное число USB-запросов старого алгоритма и проверенный
тестами предел нового: 402 → 264 на пустом чипе, 886 → 280 при нескольких отметках
и старой записи в ячейке 7E, 890 → 640 при заполненных ячейках отметок.
Это число обменов, а не замер времени
на физической станции; размер поддерживаемой памяти остаётся прежним.
Очистка нескольких ячеек не является атомарной: если чип убран, USB отключён или данные
не совпали после первой попытки записи, асинхронная команда возвращает
`Success = false`, `Failure = ClearUnverified`. Синхронный `station.ClearCard()`
сохраняет прежний контракт `SfrCardUpdateUnverifiedException`.
Результат и исключение содержат `RequestedNumber` (null при отдельной очистке) и `LastAttemptedCell`.
Чип может быть очищен частично; автоматического повтора и отката нет.
Отмена принимается до первой попытки изменения памяти, затем операция завершается
проверкой либо ошибкой с указанием неопределённого результата.

### Замеры времени

В тестовом окне кнопка «Время этапов» открывает отдельный журнал без USB-пакетов.
В нём видны начало и длительность ожидания чипа, подготовки, чтения памяти,
записи, итоговых проверок и сигнала (включая обязательную паузу 300 мс).
«ВСЯ КОМАНДА» — общее время с ожиданием чипа; это итог, его не нужно складывать
с отдельными этапами. При ошибке или отмене незавершённый этап помечается «прервано».
Записи доступны и после завершения команды; кнопка «Сохранить этапы» выгружает
последние 500 сообщений. Оба журнала обновляются не чаще четырёх раз в секунду.
DLL передаёт строки с префиксом `ЭТАП · ` в существующий callback `log`.
Длительность измеряется через `Stopwatch` на рабочем потоке, независимо от задержек
отрисовки. Замеры не добавляют запросов к станции.
