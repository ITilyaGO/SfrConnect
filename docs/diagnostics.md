## Тестовое окно

После сборки запустите `SfrConnect.TestApp/bin/Release/net8.0-windows/SfrConnect.TestApp.exe`
или из корня решения:

```powershell
dotnet run --project SfrConnect.TestApp -c Release
```

Рядом с EXE должны оставаться остальные файлы каталога сборки.

1. Закройте другие программы, использующие станцию. Нажмите «Обновить»,
   выберите устройство и нажмите «Подключить».
2. Начнётся чтение каждые 0,5 с. Само прикладывание чипа ничего не записывает.
3. Введите номер 0–39999 и нажмите «Записать». Чип можно приложить после запуска.
   «Очистить отметки при записи» включает очистку; отдельная кнопка
   «Очистить отметки, сохранив номер» не требует нового номера.
4. Держите один чип на станции до подтверждения и сигнала.
5. Уберите чип примерно на секунду. Следующую команду можно задать заранее:
   окно сначала дождётся снятия предыдущего чипа, затем появления следующего.

Служебный чип преобразуется в обычный с очисткой независимо от галочки.
Неизвестный формат не изменяется. «Отменить ожидание» действует до первой
попытки записи; после неё проверка завершается с фактическим результатом.

«Остановить чтение» приостанавливает опрос. «Отключить» освобождает соединение.
После неудачи окно отключает станцию только при необходимости переподключения
из результата DLL или при ошибке обмена. Неподтверждённая запись автоматически
не повторяется. Закрытие окна дожидается текущей операции.

## Два журнала

**Журнал обмена** содержит TX/RX, сообщения и результат. «Сохранить журнал»
выгружает последние 500 сообщений в текстовый файл. Автоматического сохранения
на диск нет; при длинной очистке ранние пакеты могут уже выйти из буфера.

**«Время этапов»** открывает отдельное окно без пакетов. Оно показывает
ожидание чипа, подготовку, чтение памяти, запись, итоговую проверку и сигнал.
«Сохранить этапы» сохраняет последние 500 сообщений этого журнала.

Строки «готово» и «прервано» содержат длительность. «ВСЯ КОМАНДА» включает
ожидание чипа и паузу после сигнала 300 мс: не складывайте итог с отдельными
этапами. Замеры выполняются в рабочем потоке; оба окна обновляются пакетами
раз в 250 мс. Задержка отрисовки не прибавляется к измеряемому этапу.

Для разбора проблемы сохраните оба журнала и укажите действие: например,
«запись с очисткой, чип снят во время итоговой проверки». Важны строки перед
неудачей, а не только последний текст результата.

## Консоль

Без аргументов запускается интерактивная консоль:

```powershell
dotnet run --project SfrConnect.Diagnostics -c Release
```

| Команда | Действие |
|---|---|
| `list` | Найти интерфейсы SFR |
| `list --all` | Показать все HID-интерфейсы без отправки команд |
| `open [n]` | Открыть и сразу закрыть соединение |
| `beep [n]` | Послать один сигнал; чип не требуется |
| `read [n]` | Прочитать номер приложенного чипа |
| `write <новый>` | Записать новый номер при одном найденном интерфейсе |
| `write <текущий> <новый> [n]` | Проверить старый номер, затем записать новый |
| `help` | Показать справку |
| `exit` | Закончить интерактивный сеанс |

`n` — номер устройства с единицы из текущего `list`, **не из `list --all`**.
При нескольких интерфейсах выбор обязателен. Каждая команда заново ищет
устройства, выводит выбранный путь, открывает соединение и закрывает его.
Поэтому `open` не оставляет соединение для следующей команды.

Примеры разовых вызовов:

```powershell
dotnet run --project SfrConnect.Diagnostics -c Release -- list
dotnet run --project SfrConnect.Diagnostics -c Release -- open 1
dotnet run --project SfrConnect.Diagnostics -c Release -- read 1
```

`write 2 3 1` действительно меняет номер с 2 на 3 на первом интерфейсе.
CLI использует синхронный API: чип должен уже лежать на станции, автоматического
сигнала после записи нет. Отдельной команды очистки в CLI нет; используйте
тестовое окно или `ClearAsync` из DLL. Запись служебного чипа и в CLI включает
его преобразование с очисткой.

В разовом режиме код завершения 1 означает исключение, 0 — завершение без
исключения. Пустой результат `list` и ответ «чип недоступен» при `read` дают 0;
этот код сам по себе не доказывает наличие чипа. Журнал можно перенаправить:

```powershell
dotnet run --project SfrConnect.Diagnostics -c Release -- read 2>&1 | Tee-Object -FilePath .\sfr-diagnostic.txt
```

## Разбор типичных ситуаций

| Наблюдение | Значение и действие |
|---|---|
| Станция не найдена | Проверить USB и `list --all`; текущий профиль ожидает VID `2047`, PID `0301` |
| Найдена, но не открывается | Сохранить исключение; проверить другие программы и дескриптор HID |
| Начальное чтение вернуло `2A 06` | Чип сейчас недоступен; это не потеря USB и не доказательство неподдерживаемой памяти |
| `PreparationFailed` | Подготовка очистки закончилась без записи; можно снова запустить команду |
| `WriteUnverified` / `ClearUnverified` | Данные могли измениться; вернуть чип, проверить состояние, не считать операцию успешной |
| Ответ записи `2A 08` | DLL проверяет записанные данные чтением; сам код не подтверждает успех и не вызывает повтор записи |
| `RequiresReconnect = true` | Завершить задачу, закрыть соединение, открыть заново; при изменившемся пути повторить поиск |
| Тайм-аут HID | Станция не ответила в срок; это отличается от корректного ответа об отсутствии чипа |
| `Success = true`, `SignalSent = false` | Данные подтверждены, но отправка сигнала завершилась ошибкой; не повторять запись ради звука |
| Очистка заметно дольше записи номера | Читается и проверяется диапазон 02–7F, даже если изменяются всего несколько ячеек |

Срок возврата чипа по умолчанию 5000 мс. Он настраивается при открытии DLL,
а не через поле тестового окна; детали — в [руководстве по внедрению](integration.md).
Автоматические тесты используют имитацию транспорта и не заменяют проверку
конкретной модели станции.
