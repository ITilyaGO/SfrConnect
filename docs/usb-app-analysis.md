# Разбор SFR smart terminal 0.12.1 и проверка чипа 7020

[Протокол](protocol.md) · [Диагностика](diagnostics.md)

Исследован предоставленный `base.apk`: пакет
`com.danser.home.sfr_smart_terminal`, версия `0.12.1`, размер 1 868 607 байт.
SHA-256: `7D16BD7A7E37F30517236E2678C6B87F549725E0787A43A32C8D847F84280CE0`.
Анализ выполнен 3 ноября 2026 года без установки и запуска APK. JADX сообщил
две ошибки декомпиляции; выводы ниже относятся к найденным читаемым участкам,
а не ко всем функциям приложения. Имена классов обфусцированы.

## USB-обмен

`com.danser.sfr.c.b.m` формирует тот же 64-байтовый отчёт с Report ID `3F`,
границами `FD/FE` и командами `01` (чтение), `02` (запись), что и SfrConnect.
Устройство выбирается по VID `2047`, PID `0301`. Приложение использует Android
USB Host API, `claimInterface` и `bulkTransfer`; DLL использует Windows HidSharp.

- Передача отчёта: тайм-аут 100 мс.
- Получение ответа: тайм-аут 200 мс.
- Перед всей операцией в `com.danser.sfr.b.b.a(callback)` установлен флаг занятости
  и выполняется `Thread.sleep(50)`. Это не пауза перед каждой ячейкой.
- Опрос присутствия через USB выполняется примерно каждые 300 мс, через чтение
  ячейки 00. Во время операции флаг занятости подавляет такой фоновый обмен.
- Явная постоянная пауза между ячейками и повтор каждой неудачной записи
  в разобранном пути не обнаружены. При отсутствии USB-ответа соединение может
  освобождаться; это не то же самое, что корректный ответ `2A 06`.

## Присвоение с очисткой

`com.danser.sfr.d.c.i` при включённой очистке вызывает поиск границы из
`com.danser.sfr.b.b.e()`:

1. Начальные границы — 0 и 128.
2. Прочитать среднюю ячейку.
3. Если она нулевая, сдвинуть верхнюю границу; если непустая — нижнюю.
4. Повторять до соседних границ. При неуспешном чтении поиск прекращается.
5. Верхняя граница передаётся в формирование диапазона записи.

Получается около семи чтений. Счётчик ячейки 04 в поиске не используется.
Алгоритм предполагает непрерывную занятую область с пустым хвостом: отдельная
старая отметка после пустого промежутка может быть пропущена. Для полностью
заполненной памяти граница может получиться 128; этот крайний случай нельзя
переносить как разрешение записи за поддерживаемой ячейкой 7F.

В карту записи включается диапазон от 00 до найденной границы, время в 01,
номер в 03 и `05000000` в 04. Остальные значения обнуляются. Отдельная полная
очистка в `com.danser.sfr.d.c.g.j()` формирует диапазон 00–7F.

Запись карты в `com.danser.sfr.b.b` выполняется последовательно. После каждой
записанной ячейки приложение читает её и сравнивает данные; при несовпадении
возвращает неуспех. Сигнал отправляется после успешной записи всей карты.
Отдельного полного прохода проверки всей памяти в этом пути нет.

Это отличается от DLL: SfrConnect сохраняет ячейку 00, в сокращённом режиме
сначала читает весь поддерживаемый диапазон, пропускает ненужные записи и
делает итоговый проход до фактически найденной последней непустой ячейки.
Двоичный поиск из APK в DLL не перенесён.

## Физическая проверка

На приложенном пользователем чипе прочитаны номер **7020** и заголовок
`13 00 F0 00`. Полное успешное чтение показало непрерывные отметки 05–13,
в 05 — старт `F1`, в 13 — финиш `F0`, далее пустой хвост.

Без искусственной паузы один проход дал 118 успешных чтений из 127, остальные
ответы — `2A 06` на разных адресах. Три пробных поиска границы по алгоритму APK
без пауз между запросами дали два успеха (`lastOccupied=13`, `firstEmpty=14`)
и один отказ чтения на ячейке 10. Следовательно, перенос поиска сам по себе
не устранил нестабильность обмена.

При паузах 5, 10, 15 и 30 мс диагностические полные проходы читали 127/127
ячеек. Это результат ограниченного числа опытов на одном чипе, а не гарантия
совместимости всех моделей. Пауза в этих опытах задавалась диагностической
обёрткой перед TX; новой настройки задержки в DLL не добавлено.

Сокращённая очистка с такой паузой 5 мс завершилась успешно:

| Этап | Время |
|---|---:|
| Чтение памяти и подготовка | 2152 мс |
| Запись 17 ячеек с проверками | 1133 мс |
| Итоговая проверка 02–13 | 348 мс |
| Завершающая проверка номера и типа | 78 мс |
| Сигнал с паузой станции | 320 мс |
| Вся команда, включая обнаружение | 4198 мс |

Номер остался 7020, заголовок стал `05000000`, возвращены `Success = true`,
`CardCleared = true`, `SignalSent = true`. Дополнительный независимый проход
прочитал 127/127 ячеек и подтвердил нули во всех ячейках отметок 02 и 05–7F.
Ранее неудачная подготовка до этого опыта не отправляла записей.
